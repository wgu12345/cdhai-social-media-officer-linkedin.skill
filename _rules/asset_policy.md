# Asset Policy

How the skill handles images, and what happens when the user's folder has
no images or too many images.

---

## Folder convention

The skill expects:

```
user_folder/
├── content.{md,txt,docx,pdf}    # main content (required)
├── images/                       # user-provided images (strongly recommended)
│   ├── image_01.jpg
│   ├── image_02.png
│   └── ...
├── style_reference.{txt,html,pdf}   # optional, see below
└── (other supporting docs allowed)
```

`images/` is **strongly recommended**, not required. Posts without images
still produce a draft, but visual posts perform 2-3x better on LinkedIn.

---

## Phase 2 — Asset acquisition flow

Codex follows this order:

1. **Check `images/` folder**
   - If 1+ image present → use those (skip to step 4)
   - If empty or missing → continue to step 2

2. **Try extraction from content files**
   - If content is .pdf or .docx → extract embedded images automatically
   - If 1+ image extracted → present to user, ask to confirm or supplement
   - If none extracted → continue to step 3

3. **Ask the user (no images anywhere)**
   
   Show this prompt (don't auto-decide):
   
   > I don't see any images in this folder. Pick one:
   > 
   > (a) Search Unsplash for relevant CC-licensed photos
   >     (I'll suggest keywords like "Washington DC tech", "healthcare AI")
   > (b) Generate via DALL-E (flagged as AI-generated in the report)
   > (c) Proceed with text-only post
   
   Wait for user choice. If (a) or (b), present candidates and let user pick.

4. **Selection and ranking** (see next section)

---

## Image selection — pick 10, rank, let user decide

When images are available (uploaded, extracted, searched, or generated):

| Image count | Behavior |
|---|---|
| 1-9 | Use all. Rank in recommended order. |
| 10+ | Pick top 10 by semantic match to post content. Rank in recommended order. |

**Ranking criteria (in order)**:
1. Semantic match to post content (image of the keynote speaker if post is about that keynote)
2. Source priority: user-provided > PDF-extracted > Unsplash > DALL-E
3. Resolution (≥1200px wide preferred for LinkedIn)
4. Recency (newer over older if both match)

**Output to user**: `report.docx` lists the ranked 10 with a one-line reason
for each. User picks final 1-3 for LinkedIn (LinkedIn allows multiple but
1-3 is typical).

---

## Style reference (`style_reference.{txt,html,pdf}`)

**Optional but strongly recommended.** This is a URL, downloaded HTML page,
or PDF that the skill uses to learn the visual/tonal direction you want.

- For LinkedIn alone, style reference matters less — LinkedIn strips most
  visual styling on paste.
- **As CDHAI extends to web pages and visual content**, style reference
  becomes essential. Building the muscle now means a smoother transition.

If the user provides a URL that returns 403/blocked (e.g., Carey's main
site blocks bots), instruct the user to download the page as HTML or PDF
and place it in the folder. Don't fail silently.

---

## DALL-E disclosure

Any image generated by DALL-E must be flagged in `report.docx` under a
section titled "AI-generated images used":

```
## AI-generated images used

- image_07_dalle.png — generated from prompt: "modern DC tech
  workspace, professional setting, soft lighting"
  Used in: paragraph 3 (after "the DC tech corridor sentence")
```

This is for transparency to MarComm and to comply with JHU social-media
guidelines around AI content.
